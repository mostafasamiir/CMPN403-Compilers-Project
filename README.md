# CMPN403 – Simple Programming Language using Lex & Yacc

Cairo University, Faculty of Engineering. Languages and Compilers (CMP(N)403) course project.

We design and build our own programming language using **Lex (Flex)** and **Yacc (Bison)**.

---

## Phases

| Phase | Due | What we deliver |
|---|---|---|
| **Phase I** (current) | Week 11 | Lexer (`lexer.l`) and parser (`parser.y`) that accept the whole language and reject invalid syntax |
| **Phase II** | Week 14 | Symbol table, quadruples, syntax error handler, semantic analyzer |

## Language Features (Phase I)

- Variable and constant declarations
- Mathematical and logical expressions
- Assignment statements
- `if-then-else`, `while`, `repeat-until`, `for`, `switch`
- Block structure (nested scopes, declarations at the start of blocks)
- Functions
- Classes and objects: class declarations, attributes, methods, object instantiation, `.` access, method calls, and constructors (optional)

The full syntax is in [`docs/language_spec.md`](docs/language_spec.md), and every token is listed in [`docs/tokens.md`](docs/tokens.md).

## Project Structure

```
Project/
├── src/
│   ├── lexer.l              # Lex: token definitions
│   └── parser.y             # Yacc: grammar + main()
├── tests/
│   ├── valid/               # programs that MUST parse successfully
│   └── invalid/             # programs that MUST produce syntax errors
├── docs/
│   ├── language_spec.md     # language syntax
│   └── tokens.md            # token list + descriptions
├── Makefile                 # build (Linux / WSL)
├── build.bat                # build (Windows)
├── run_tests.bat            # run parser on all test files
├── WORKLOAD.md              # task division (pick your role!)
└── README.md
```

Files generated by the build (`lex.yy.c`, `parser.tab.c`, `parser.tab.h`, executables) are git-ignored. Don't commit them.

## Requirements

- **Flex** and **Bison**
  - Windows: [win_flex_bison](https://github.com/lexxmark/winflexbison) (add it to PATH), or use WSL
  - Linux / WSL: `sudo apt install flex bison`
- **GCC** (on Windows: MinGW or MSYS2)

## Build & Run

**Windows**
```
build.bat
run_tests.bat
```

**Linux / WSL**
```
make
make test
```

Run on one file:
```
compiler < tests/valid/01_declarations.txt
```

## Team Workflow

1. Pick a role in [`WORKLOAD.md`](WORKLOAD.md) and put your name next to it.
2. **Don't write grammar rules until the token names in `docs/tokens.md` are agreed.** Every part of `parser.y` depends on them.
3. Work on your own branch: `feature/<your-area>` (for example `feature/classes`).
4. Write only inside **your section** of `parser.y`. The sections are marked with comments.
5. Before opening a PR:
   - the project builds with **no new shift/reduce or reduce/reduce conflicts**
   - all of `tests/valid/` passes and all of `tests/invalid/` fails as expected
6. The Integration owner (Member 1) reviews and merges into `main`.
